# Personal Skills

可持续维护的个人 AI 学习技能。方法与模板在这里迭代，教材、学习笔记和个人掌握记录保存在各自学习项目中。

## 技能目录

| Skill | 适用场景 | 版本 |
| --- | --- | --- |
| [personal-learning-skill](personal-learning-skill/SKILL.md) | 默认推荐：概念优先、知识网络、自适应 HTML 课程、代码库入门与华为笔记衔接 | 1.5.0 |
| [learning-method-skill](learning-method-skill/SKILL.md) | 轻量学习循环：目标、尝试、反馈、变式和复习 | 0.3.0 |

两个技能是可选方案，一次学习通常选一个。完整版是当前主要维护方向；轻量版保留独立用途，不自动把不同版本的规则混在一起。

## 快速开始：复制一句话调用

在同一台电脑的学习项目中，把下面的消息发给有本地文件读取能力的助手：

```text
请读取 E:/agent/skill/personal-learning-skill/SKILL.md，
并按当前任务需要读取它引用的 references 和 templates。
用这个 Skill 带我学习本项目的课程。
开始前说明实际读取的技能版本；学习资料和进度保存在本项目，不写回公共 Skill。
```

这是让助手读取文件并执行流程，不需要先复制一份 Skill 到每个项目。本机维护目录为 `E:/agent/skill`，以后更新这一份源文件，新会话重新读取即可使用新版。正在进行的会话可明确要求“重新读取最新 Skill，保留本项目学习进度”。

仅保存到 E 盘不会自动注册到所有助手的技能菜单；只有宿主已经识别该技能时，才使用它支持的名称调用方式。找不到名称时，使用上面的完整路径消息。若助手无法访问此路径，按下方“其他电脑或云端使用”提供实际文件。

## 什么时候用哪一个

| 你的需求 | 选择 |
| --- | --- |
| 系统学一门课、读一本教材、搭建知识网络 | `personal-learning-skill` |
| 从宏观地图进入概念细节，配合 Obsidian 与华为笔记 | `personal-learning-skill` |
| 只想围绕一道题或一个卡点做简短的尝试—反馈—复习 | `learning-method-skill` |

轻量版的调用消息：

```text
请读取 E:/agent/skill/learning-method-skill/SKILL.md。
我想练习的是：【题目或知识点】。
我已经尝试：【我的步骤】；卡在：【具体位置】。
请按这个 Skill 检查第一处错误，先给最小提示，等我继续尝试。
```

## 开始一门新课程

复制下面的消息，替换括号中的内容；不清楚的写“待确认”：

```text
请读取 E:/agent/skill/personal-learning-skill/SKILL.md，
以及当前任务需要的引用文件。

课程：【例如概率论、英语、日语或 Python】
目标与期限：【希望独立完成什么，什么时候需要达到】
基础与每天可用时间：【已有基础；可用时间】
教材或资料：【实际文件路径或已上传附件；没有则写暂无】
本项目学习记录位置：【可访问目录，或先在对话中交付】
Obsidian 笔记库位置：【实际路径，或暂不使用】

先建立知识全景、前置依赖、知识关系、跨学科连接四个视图。
地图要能从全景进入模块关系，再进入概念细节。
以模块为单位先理解概念、条件、例子反例和推导，
再集中整理题型元模型、解题方法、二级结论和应试技巧。
教学先给完整连贯的解释和示例，再让我独立尝试；卡住后逐级提示。

我主要在华为自带笔记里手写，Obsidian 作为导航和关联媒介。
需要手写时给无答案学习页，不要求我逐字抄写参考卡。
这是新课程，请单独建立能力记录，不继承其他课程的掌握状态。
先说明实际读取的 Skill 版本，再开始。
```

完整可调整版本见 [新项目启动模板](personal-learning-skill/templates/project-start.md)；时间、复习间隔等参数见 [个人设置模板](personal-learning-skill/templates/learner-profile.md)。复制设置到学习项目后修改，单门课的偏好不直接改公共模板。

## 每次学习怎样继续

完整版的新课程工作区为：`mission.md`（目标）、`resources/`（资料）、`lessons/`（HTML 课件）、`glossary/`（术语与概念）、`solve-cards/`（解决问题卡）、`notes.md`（理解变化与索引），另有 `.learning/` 保存进度。已有目录不强制迁移。

正式课程用 HTML 承载交互、分步图解、测验与按需提示；Markdown 保留可检索的术语、链接和记录。HTML 页面不会默认自动更新课程状态，需把作答结果交回助手。导出到华为笔记的 PDF 是静态练习页。

你可以说：“我已经学到【内容】，能独立做【任务】，卡在【问题】，今天有【时间】；请先结合进度诊断，再为我定做下一节 HTML 课。”助手会按真实表现选择有限帮助后可推进的挑战，过易增加一个变化维度，过难补前置与支架，不用固定正确率判断能力。

熟悉代码库时可说：“用这个 Skill 带我 onboard 到【仓库路径】，目标是【独立追踪/解释的行为】；先只读，沿真实入口、领域术语和一条数据路径诊断并设计入门课。”详见 [课程设计与工程分支](personal-learning-skill/references/course-design.md)。

已有课程不要每次从零建图。可直接发送：

```text
继续本项目学习。重新读取 E:/agent/skill/personal-learning-skill/SKILL.md，
读取本项目已有个人设置、CURRENT 或最新接续记录、相关知识图和能力证据。
先处理当前待答任务或到期复查，再继续下一个知识点。
保留已有进度，不重复初始化；找不到记录时明确说明，不猜测我学到了哪里。
```

从另一个会话继续时，带上本项目的接续记录或可访问路径。Skill 保存的是学习方法，课程文件保存的是你的进度；GitHub 不会自动知道你已经学会什么。

## 像教师一样构建体系与指导记录

完整版先建立“核心问题—模块—节点—验收”的课程计划，四图由总览进入概念细节；每课定位当前内容，模块结束检查缺口与跨模块联系。每课明确告诉你图上补哪条关系、细节放哪个节点、哪项理解变化值得手写，再根据实际作品反馈。轻量版保留相同方向，按当前局部逐步展开。

优先提供课程大纲、一本主教材和实际作业/难点；不必一次上传全部资料。无教材也能开始，由 agent 核验公开课程或官方文档作为主线。上网主要补充解释、前置与应用，来源回链已有节点。详见 [教师指导](personal-learning-skill/references/teacher-guidance.md)。

在 ChatGPT 网页项目中提供 Skill 文件及必要引用材料；本机路径不会自动成为项目文件。项目上下文辅助接续，精确进度仍需保留明确版本的课程档案或接续包。无文件写入能力时，将最新接续摘要保存为项目来源，并标明修订号；旧摘要标为历史，避免多份“当前进度”。这不是本地档案自动同步功能。

## 有状态：换会话后从哪里接着学

两个 Skill 都采用 [有状态学习协议](personal-learning-skill/references/state-protocol.md)：助手每次先读状态，再教学，有新进展就写入并读回。状态是课程中的持久文件；不是后台运行服务，也不意味着助手凭空获得跨设备记忆。

明确课程目录后，默认在其中创建 `.learning/`；已有指定目录继续沿用。每门课有独立 `project_id`。公共 Skill 放在 `E:/agent/skill`，实际课程记录放在课程目录或个人笔记库，不提交到本公开仓库。

```text
你的课程目录/
└─ .learning/
   ├─ MISSION.md          课程身份、目标和范围
   ├─ LEARNER-PROFILE.md  本课程偏好
   ├─ RESOURCES.md        教材与实际已读范围
   ├─ CURRENT.md          当前活动、修订号、准确待答问题与下一步
   ├─ NODES.md            节点掌握状态与证据索引
   ├─ REVIEWS.md          复查日期、任务与结果
   └─ learning-records/   每次有意义进展的事件记录
```

可直接这样说：

```text
用 personal-learning-skill 继续这门课。
课程目录是：【实际课程路径】。
先读取已有状态；若尚未创建，在该课程目录的 .learning/ 初始化。
恢复上次的待答任务，保留提示级别和能力证据。
本轮每次有意义反馈后保存，结束时说明保存位置与唯一下一步。
```

常见操作：

| 你说的话 | 助手应做的事 |
| --- | --- |
| “继续” | 读取本课程记录，恢复原问题，不重新开课 |
| “今天先暂停” | 保存卡点、最后提示与待答任务，记录暂停前活动 |
| “先跳过这里” | 记录跳过，保留未验证状态，按你的目标继续 |
| “换成轻量版” | 复用同一课程状态，改变教学流程，不重建进度 |
| “开始另一门课” | 建立新的课程身份与目录，不复制掌握证据 |
| “旧版记录也要保留” | 备份后补齐缺失字段，有依据才迁移能力状态 |

未回答不会被写为掌握；复习到期不会被写为完成。保存失败必须明确说明并给可复制的接续包。文件冲突、损坏或更高版本格式不能静默覆盖；同一课程默认单个会话写入，文件协议不提供数据库级并发锁。

技能升级不重置课程。跨设备需要同时带走课程状态和相关材料，仅更新 GitHub 上的 Skill 不会同步个人进度。协议版本与技能版本分别记录，模板见 [learning-state.md](personal-learning-skill/templates/learning-state.md)。

## 电脑、Obsidian 与华为笔记怎么配合

1. **电脑端定位：**在 Obsidian 查看学科地图，进入当前概念卡，理解定义、条件与联系。
2. **准备本轮任务：**让助手按 [平板学习页模板](personal-learning-skill/templates/tablet-session.md) 生成无答案任务；能生成并检查 PDF 时再导出。
3. **平板端学习：**在华为笔记中闭卷重画关系、解释概念、推导和做题；不要把电脑正文再抄一遍。
4. **反馈与归档：**提供手写作答给助手检查；按设备实际支持的 PDF/图片形式导出有价值的记录，关联回对应节点。
5. **最小更新：**只把问题、错因、关键依据、修正策略、关联节点和复查任务写回学习记录。

参考 [概念卡模板](personal-learning-skill/templates/concept-card.md)、[学习记录模板](personal-learning-skill/templates/study-record.md) 和 [联动规则](personal-learning-skill/references/obsidian-tablet.md)。华为笔记的机型、版本与传输方式需要实际核验；这里没有安装同步服务，PDF 也不等于可双向编辑的 Obsidian 地图。

## 其他电脑或云端使用

**另一台电脑：**在选定的父目录打开终端，然后克隆仓库：

```sh
git clone https://github.com/QCYM-qcym/personal-skills.git
```

克隆后将调用消息中的路径换成该电脑的实际目录。技能文件完整保留，课程资料与学习记录另行传递。

**云端或网页助手：**在 GitHub 仓库页面选择 Code → Download ZIP，解压后提供所选技能的整个目录内容，包括主文件、references/ 和 templates/。若宿主支持 ZIP 解包可上传压缩包，否则上传相关文件。要求它先读取主文件及引用文件；缺文件时补齐。提供 `E:/...` 路径本身不能让云端读取你的电脑。

**固定版本：**需要复现某次学习流程时，选择仓库中的版本标签，例如 `personal-learning-skill-v1.2.0`。默认分支会随更新变化，标签对应的旧版本不会自动获得新规则。

## 修改与更新

可直接向有权限维护本仓库的助手发送：

```text
请修改 E:/agent/skill 中的【Skill 名称】：【观察到的问题与期望变化】。
先读取现有文件，保留其他修改；更新对应版本和更新记录，完成检查，
然后提交并推送到 QCYM-qcym/personal-skills。
只提交本次相关文件，不上传教材、学习记录或凭据。
```

如果只想试用修改，将最后一句发布要求改为“先只修改本地，暂不提交推送”。这些操作需要实际可用的文件权限和 GitHub 登录，不是 Skill 自动后台执行的功能。

1. 先记录具体使用问题、预期行为及实际表现，可使用 Issues 中的改进模板。
2. 小步修改对应 Skill；参数改模板，流程改主文件，条件性细节改 references/。
3. 修改 Skill 行为时更新技能版本及其修改记录，并在 [CHANGELOG.md](CHANGELOG.md) 记录仓库级变化。仅改 README 等仓库使用说明时无需提升技能版本。
4. 安装检查依赖并检查文件：

   ```sh
   python -m pip install -r requirements-dev.txt
   python scripts/validate_skills.py
   python -m unittest discover -s tests
   ```

5. 对影响教学行为的修改，再实际跑相关场景。静态检查通过不代表教学效果已验证。
6. 检查差异后提交和推送。重要版本创建单独的技能标签，例如 `personal-learning-skill-v1.2.0`。后续标签不复用、不覆盖。

日常由本地编辑、Git 提交保存历史、GitHub 同步备份；其他电脑更新前先提交自己的改动，再执行 `git pull --ff-only`。出现冲突时按双方意图合并，不直接覆盖。

两个技能独立分发，因此各自包含状态协议与模板。维护时以完整版的这两个文件为源，同步到轻量版；自动检查会验证分发副本一致，避免同一课程在切换技能后出现两套状态规则。

## 内容与分发

- 源文件是维护依据；旧 ZIP 和便携合并稿保留在本地，不加入 Git 历史，避免多个版本混淆。
- 不上传教材 PDF、个人学习记录、设备配置或凭据。忽略规则只是辅助，提交前仍应检查文件清单。
- 结构借鉴及原始来源见 [设计依据](personal-learning-skill/references/design-notes.md)。本项目并非上游作者的官方作品。
- 当前未选择开源许可证。公开可见不等于授予任意复制、修改或再分发授权；如果计划开放复用，后续明确许可证并保留必要的第三方声明。
