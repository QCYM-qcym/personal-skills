# 有状态学习协议 v1

本文件是状态读写规则，不是当前用户的学习记录。每次启用或续学先读取它。使用本协议的学习 Skill 共用兼容格式，同一课程切换 Skill 时复用同一状态目录。状态是外部文件，不是模型自动永久记忆；仅在会话实际运行且可写文件时更新。

## 1. 找到正确的课程

依次使用用户明确的状态位置、项目已有 CURRENT/NOTES 指向的位置、当前课程根目录下的 `.learning/`。默认目录只适用于已明确属于某一课程的项目；通用空白任务或包含多个课程且无法辨认时，先问课程及保存位置，继续提供不依赖状态的解释。

新课程创建独立 `project_id`（稳定的课程标识或 UUID），记录课程名、根目录及范围。读取后核对课程与用户当前意图；ID/课程冲突时停下状态写入并说明，不把旧课程覆盖成新课程。搬动同一课程目录保留 ID，记录新路径；创建另一课程时只继承用户选定的偏好，不复制掌握证据。

不得把运行中的状态放在公共 Skill 仓库或上传到该仓库。目录可在学习项目或个人 Obsidian 库内；只要其明确属于该课程即可。

## 2. 文件职责与唯一依据

将 [状态模板](../templates/learning-state.md) 中各段按需创建为独立文件；已有文件沿用，补缺字段即可，不批量覆盖。

若课程有根目录 mission.md 或 resources/index.md，状态目录的 MISSION.md/RESOURCES.md 可只写 project_id 与到正文的相对路径；读取时跟随明确指针，只维护一份正文。不得只读指针就宣称已读取目标/材料。CURRENT 中可增加 lesson_id、lesson_path、diagnosis_ref 和 scaffold_plan 以接续定做课程；这些是可选字段，旧状态无须重置或升级 schema。notes.md 若是展示摘要，须链接 CURRENT 并标 revision，不作为第二份状态权威。

| 文件 | 唯一负责的内容 | 初始值 |
| --- | --- | --- |
| MISSION.md | project_id、课程、范围、目标与验收 | 根据用户输入；未知明确写待确认 |
| LEARNER-PROFILE.md | 本课程偏好、时区、路径与提示节奏 | 沿用已有设置 |
| RESOURCES.md | 材料、版本、实际已读范围、来源缺口 | 无材料时为空或待核验 |
| CURRENT.md | 协议版本、技能版本、修订号、当前活动/节点、最后提示与唯一下一步 | revision=0；未开始；无掌握推断 |
| NODES.md | 节点 ID、前置、能力状态、证据与复查需要 | 新节点为待学 |
| REVIEWS.md | 复习任务 ID、节点、到期时间、状态及结果记录链接 | 无任务时为空，不虚构日期 |
| learning-records/ | 已发生事件及用户作答证据，按唯一事件 ID 新增 | 不复制整个聊天历史 |

地图、六项笔记和 CURRENT 只引用详细证据；完整题目/答案/手写附件只在其原文件保存。节点掌握状态以 NODES 为准，复习任务以 REVIEWS 为准。只有当前教学问题原文与必要上下文保存在 CURRENT，确保换会话后能继续，而非只留下“继续学”。

NODES 的最近证据必须指向实际作答或验证事件；暂停、搬动目录、调整偏好等事件不替换该证据指针。最近发生的事件另由 CURRENT.last_event_id 表示。CURRENT/MISSION 等 Markdown 文件中的结构化字段优先使用 YAML 前言，并保留已有兼容格式，迁移时不为排版改写用户内容。

教学记忆的归属：课程计划与覆盖缺口保存在 MISSION 正文；长期节奏偏好在 LEARNER-PROFILE；实际误解、首错与修正及相关图/笔记路径保存在作答事件，NODES 链接证据。地图引用节点能力，不另存一套等级。教学推测标待验证，不升级成用户的固定能力标签；用户更正时追加事件并更新当前判断。新会话读取相关证据后才引用历史诊断；缺文件时明确记忆缺口。

## 3. 每次开始的读取顺序

1. 读取 MISSION、个人设置和 CURRENT，检查项目、协议版本与 revision。
2. 按 CURRENT 的链接读取当前节点、相关证据与到期复习；不全量重读所有日志和教材。
3. 检查上次写入是否完整（见第 6 节），有未完成提交先恢复。
4. 用户本轮明确任务优先；否则先接续待答问题，再处理到期复查，再选前置足够的下一节点。复习到期不改变原有能力证据。
5. 用一两句话说明“上次停在何处、现在做什么”，直接开始。不得把“继续”解释为从头建图或让用户再次填写已知信息。

一门课只选择一个当前活动状态：`未开始 / 讲解中 / 等待作答 / 反馈修正 / 待验证 / 已暂停 / 本轮完成`。暂停时保留原活动与待答任务；恢复时接回，不能把暂停当掌握。

选择规则：初次出题后用等待作答；针对首错给提示后用反馈修正（pending_task 保留待改问题）；纠正后发新变式用待验证；明确暂停优先于其他活动并保存 resume_activity。“结束这一轮”但问题尚未回答时保留该问题，不能标本轮完成。用户回来明确要求继续后才保存恢复事件，单纯读取预览不改变暂停状态。

## 4. 能力与任务状态转换

| 事件 | 可以做的更新 | 不应推断 |
| --- | --- | --- |
| AI 讲完或用户说看懂了 | 当前活动进入等待作答，记录问题 | 提升节点能力 |
| 用户在提示后完成 | 节点记有提示可做，附提示级别与实际证据 | 独立通过 |
| 无提示解释关键条件并完成变式 | 节点记即时独立通过，创建复查任务 | 延迟通过 |
| 后续不同时间闭卷验证通过 | 节点记延迟验证通过，记录时间与结果 | 永久掌握 |
| 后续失败或暴露基础误解 | 按本次证据更新能力、记待巩固与首错，保留旧成功记录 | 删除历史或一律判为完全不会 |
| 复习时间已到但用户未做 | 任务仍待做，显示到期；能力不变 | 任务完成或能力下降 |
| 用户要求先跳过 | 记录跳过原因与下一步，保留未验证状态 | 把跳过当通过 |

节点能力使用 `待学 / 有提示可做 / 即时独立通过 / 延迟验证通过`。复习任务使用 `待做 / 已完成 / 已取消`；延期修改 due 并留事件，完成后下次复习新建 ID，不能抹掉上次结果。日期带用户时区，未知时先确认或使用明确的相对触发条件；不得凭空判断“今天到期”。

仅说“明天再学”时将接续时间记在 CURRENT 的 next_action，已有复查照常保留；只有明确安排了检验任务及通过标准才新增 REVIEWS 行。接续原来的提示题不算新的独立闭卷验证。

个人笔记沿用所选 Skill 的格式；它们与本协议的能力账本相互链接，不要求合并成同一张长表。

## 5. 何时保存

在给出待答任务、收到有效尝试并反馈、升级提示、更换节点、调整复习/目标/偏好、暂停或结束时保存。普通闲聊或无新信息的解释不追加重复事件。用户尚未作答时保存“等待作答”和准确问题，不等到整课结束才记录。

事件含：event_id、project_id、发生时间与时区、base_revision、target_revision、事件类型、涉及节点/任务、用户证据或来源链接、状态前后变化和明确下一步。没有用户证据时不造答案；用户自述与助手已检查的作答分开标记。每次保存后 CURRENT 显示最新事件 ID 与递增 revision。

## 6. 写入、冲突与中断

默认单写入者：同一课程同一时间由一个会话更新，不把普通文件协议声称为数据库事务或自动合并系统。

1. 写前重新读取 revision；与开始时不一致就重新载入并核对本轮变化，不覆盖别的会话更新。有真实冲突时保留双方记录并让用户选择要接续的活动。
2. 先用不会复用的 ID 保存事件（包含预期变更），再更新 NODES/REVIEWS 等必要文件，最后更新 CURRENT 的 revision 和 last_event_id，作为本次提交标记。保留未知字段和用户注释。
3. 写完读回相关文件，核对项目、修订号、证据链接和唯一待答任务；成功才说“已保存”。事件 ID 已提交则不重复应用，不生成第二条同内容复查。
4. 若事件存在而 CURRENT 未到 target_revision，视为未完成写入：检查各文件是否已应用该事件，只补缺少的变更，再提交 CURRENT。若存在不相关的新修改或多个并发事件，暂停自动修复，说明冲突，不能简单按最新时间覆盖。
5. 文件损坏或关键记录缺失时保留原件，依据事件与用户记录提出恢复内容；依据不足标待确认，不伪造已掌握状态。写入失败时明确“本轮未保存”，提供完整接续摘要供用户保留。

协议能指导有文件能力的助手接续，不提供系统级锁、实时同步或定时提醒。多设备同步须先确认文件齐全，再由单个会话写入。

## 7. 旧项目迁移与无文件模式

已有 MISSION/CURRENT/NOTES 时，先保留备份，沿用路径、目标、节点及原证据；为缺失 ID/修订号补初始值，记录“迁移”事件。只把有证据的历史映射到新能力状态；“已看完”“已熟悉”保留原描述但标未验证。不为迁移重做课程或删除旧笔记。

技能版本与 `state_schema: 1` 分开管理。更新 Skill 不自动重置项目；遇到高于本协议的 schema 时只读并要求兼容迁移，不降级覆盖。

无持久文件能力时按模板在对话给出“未落盘接续包”，包含项目、目标、版本/修订、当前任务、节点状态及证据、复查和下一步；明确需要下次重新提供。有文件但只读时也不能声称已保存。不要在未获得文件时承诺跨会话记忆。
