# 项目初始化、Teach组合与迁移

本文件处理跨学科与跨宿主的持久化。所有学科路径、目标、截止时间、材料、能力证据属于项目；技能包只保存通用流程。

## 1. 接续或初始化

先识别新项目还是同一项目续学。读取已有 MISSION、个人设置及 CURRENT，沿用用户已提供的信息；新学科只继承明确选用的教学偏好，不继承另一学科的掌握状态、考纲或路径。

采用 templates/learner-profile.md。缺失但不影响开课的信息标待确认；只问最影响当前安排的一项。保存前核对记忆位置与笔记位置，用户指定的位置优先。未指定时先在对话交付建议结构；路径本身不代表当前环境能访问。

## 2. 存放与接续契约

| 位置 | 内容 | 更新时机 |
| --- | --- | --- |
| 记忆目录/MISSION.md | 为什么学、可观察验收、时间与范围 | 初始化；用户确认目标变化时 |
| 记忆目录/LEARNER-PROFILE.md | 学科、语言、节奏、来源、输出与两类路径 | 明确偏好变化时 |
| 记忆目录/RESOURCES.md | 已读取的可信来源、用途、版本与材料缺口 | 新材料核验后 |
| 记忆目录/CURRENT.md | 当前节点、证据、状态、最后提示、唯一待答任务、下一复查 | 每个有意义的反馈或换点后，替换旧当前状态 |
| 记忆目录/learning-records/ | 非显然能力证据、已纠正误解、目标变化 | 有新证据时递增新增 |
| 笔记目录 | 导航、四图、六项笔记、lessons/、reference/、assets/ | 有教学价值的产物产生时 |

已有项目不强制改名重排。NOTES 若承载当前状态，可继续使用，但整理成一个明确的最新接续区，历史证据留学习记录。每轮对话反馈及时给出，例行文件操作不应变成冗长的教学打断。

完全没有持久文件工具时：以相同字段在对话提供精简“接续包”，说明需用户保留并带到下次会话；不要声称已写入文件或能自动跨项目记忆。有可下载文件但无本地盘访问时：交付文件供导入，不声称写到用户电脑的路径。

## 3. Teach 的可移植部分

默认执行本节；若用户同时指定可访问的 Teach，读取并尊重其具体要求，在项目设置记录组合关系。

- 目标驱动、依据可信原始资料，不把模型记忆当作教材核验。来源不足时标通用补充与待核验，不杜撰引用。
- 每课一个可检验动作，短而完整、便于回顾；对话承担即时互动，用户作答后给予针对性反馈。
- 支持文件时将正式教学单元保存为 lessons/ 下的递增 HTML 课件，复用 assets/ 样式和组件；课件含直觉、规则、例子、实践、原始来源、提问提示及已有参考/课程链接。默认答案不提前展示。
- reference/ 提供压缩知识与术语；错题卡保留个人理解变化，不抄成第二本教材。
- 生成 HTML 后检查引用及可用的渲染结果；没做视觉检查就明确其验证范围。宿主无法生成文件时先用对话/Markdown 交付同样内容，不为创建漂亮课件阻塞教学。
- 现实运用需要时推荐高质量实践社区；尊重用户偏好，不替用户向社区发送内容。

## 4. Obsidian 分支

需要从宏观地图进入概念详情或配合平板手写时，读取 [分层知识地图与平板学习](obsidian-tablet.md)。沿用本文件的状态与路径契约；Obsidian 主知识内容优先 Markdown，HTML 课件按需补充，不为同一内容强制维护两个完整版本。

用户选 Obsidian 时用 Markdown 双链连接导航、笔记与节点。要求白板时交付真正的 `.canvas`，不是把图片或 Mermaid 改扩展名。使用当前 JSON Canvas 规范，校验 JSON、节点 ID 唯一、边引用、节点尺寸与重叠；文件节点使用相对仓库根目录的实际路径。更新保留用户编辑和稳定节点 ID，不重建覆盖整个白板。

无白板需求时，四图可用一个 Markdown 文件内四个小视图。保持来源与状态可读，跨学科联系不足就标缺口，不为填图制造关系。

## 5. 带到另一个项目

用户可复制 [新项目启动消息](../templates/project-start.md)，填写新目标与位置。

同一项目迁移：带技能包（主文件及所引用的 references/templates）和该项目接续包。不同学科新开：带技能包及选定偏好，重新诊断与建模。用户只提供本地绝对路径而新宿主不可访问时，说明需要传入实际文件或粘贴内容；不尝试猜本机内容。

仅放置文件或上传附件不等于宿主已经安装技能。宿主支持技能时按其实际入口调用；否则把通用便携说明作为项目指令/参考材料并明确采用。不得承诺所有 Work 产品都有相同的设置或自动发现机制。
